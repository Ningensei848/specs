# 仕様の明確化 (clarify.md)

本ドキュメントは、メタプロンプト最適化エンジン（.specify/spec.md）の実装計画（plan.md）を策定するにあたり、設計上の曖昧さや選択肢を排除し、仕様を確定させた記録である。

## 1. ターゲットトークナイザーとBPE最適化のスコープ

プロンプトのセマンティクス密度 $D_{\text{semantic}}$ は、特定のトークナイザーの圧縮率に依存する。本メタプロンプトは、以下の設計思想に準拠する。

-*[確定仕様]：C. ユーザー入力での指定（動的切り替え）**
- **デフォルト挙動：** GPT-5系ネイティブモデルのトークナイザー仕様（o200k_base からの進化を想定）をデフォルトのターゲットとし、将来的な陳腐化を防止する。
- **拡張性：** ユーザーから指示がある場合は、特定モデル（Claude 3系列など）のトークナイザーに動的に切り替えて最適化（体言止め、英語化、助詞排除など）を行う。

## 2. BPE圧縮における「可読性」の許容限界

極限までトークンを圧縮する際、生成されるプロンプトの「人間に対する読みやすさ（可読性）」の許容限界について。

-*[確定仕様]：B. ハイブリッド表現の許容**
- **基本設計として：** 指示ロジックを英語（トークン効率高）、要件や背景を日本語でブレンドし、MarkdownやXML/YAMLで構造化する。
- **将来的なアセット構築：** 極限圧縮（C）を選択した際の意味損失（セマンティクスの欠落）を検証・修正するための「検証専用カスタムエージェント（プロンプト）」を別個に設計する。

## 3. 自己検証ループ（Self-Verification）の実装方式

CopilotやChatインタフェース（1ターンの出力）において、メタプロンプトが「生成したプロンプトを自分でチェックして修正する」ループの実現方式。

-*[確定仕様]：C. チェックリスト・スコアリング式「ユーザー主導ループ」（可視化ハイブリッド型）**
- 最適化プロンプトを出力する際、AI自身による「自己評価シート（圧縮率、曖昧度の排除、コアセマンティクスの維持）」をレポートとして必ず併記する。
- 各チェック項目が不合格の場合、またはユーザーが微調整を求める場合に、チャットUI上で即座に実行可能な「リトライ用の構造化フィードバック文（例：/retry [理由]）」をAIから提示する。これにより、高い透明性と人間主導の確実なコントロールを実現する。

## 4. プロンプト改善における「プロジェクト憲章」の参照

改善対象となるプロンプトは、プロジェクトごとの開発憲章（例えばこのアセットにおける constitution.md）の設計思想に準拠して改善されるべきか。

-*[確定仕様]：A. 汎用的なプロンプト改善のみを行う**
- **背景：** 一般の組織ユーザーはSDD（仕様駆動開発）プロセスや構造化表記に関する専門知識に乏しい。
- **設計方針：** 入力されたプロンプト単体から徹底的に無駄を削ぎ落とし、曖昧さを排除する「汎用的かつ高精度な改善」を最優先目標とする。憲章の知識がないユーザーでも、コピペするだけで即座に高品質なプロンプトを得られるインターフェースを構築する。
