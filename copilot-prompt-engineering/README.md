# Copilot / Copilot Studio コンテキスト（会話履歴）管理まとめ

## 1. MS Teams 付属の標準 Copilot (M365) の運用
- 仕様: Claudeの `/compact` に該当するコマンドは存在しない。
- 運用フロー: 
  1. チャット上で「これまでの決定事項を次のチャット用に200文字で要約して」と指示。
  2. 出力された要約をコピーする.
  3. 「新しいトピック（ほうきアイコン）」を押してセッションを完全リセット。
  4. 新しいセッションの1発目に要約をペーストして会話を再開する。

## 2. Copilot Studio カスタムエージェントでの実装（開発者側）
Teams上のエージェントは会話履歴が永続化しやすく、コンテキストオーバーフロー（トークン上限）や過去の記憶の引きずりを起こしやすいため、以下のいずれかで制御します。

### 💡 対策A：究極の一発クリアコマンド（Teams標準機能）
- ユーザーへの案内: 「挙動がおかしい場合は `/debug clearstate` と入力してください」
- 効果: Copilot StudioがTeams向けに持つ特殊なデバッグコマンド。会話状態・履歴を完全消去し、コネクタキャッシュを削除して最新バージョンのエージェントを強制再ロードする。

### 🛠️ 対策B：履歴クリアの自動化・トリガー実装（トピック構築）
- トリガー条件: ユーザーが「/clear」「リセット」と発言した時、または「一定時間操作がない（非アクティブ）」時。
- 配置ノード: 「変数の管理」 ➔ 「変数の値をクリア (Clear variable values)」
- 設定: セッション変数だけでなく「現在のセッションの会話履歴」を明示的に選択してクリアする。
- 注意点: デフォルトのシステムトピック「会話のリセット」はグローバル変数しか消さないため、この履歴消去ノードを独自に配置するのがベストプラクティス。

### 📝 対策C：プロンプトによる疑似コンパクト（指示文の注入）
- 設定方法: エージェントの「指示（システムプロンプト）」の末尾に以下をそのまま貼り付ける。
```text
【コンテキスト圧縮ルール】
ユーザーが「/compact」または「ここまでの内容を記憶して」と入力した場合、
あなたはこれまでの会話の最重要ポイント（前提、決定事項、現在のタスク）のみを簡潔なサマリー（1つのセクション）として出力してください。
それ以降の会話では、過去の詳細な履歴ではなく、そのサマリーのみをコンテキスト（前提知識）として扱い、回答を継続してください。
```
